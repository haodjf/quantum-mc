# 服务器运行与参数扫描指南（QuantumMC / MCWF）

本指南面向“在 Linux 服务器上批量跑 Julia 轨迹仿真”的场景，重点回答：

1. 如何部署与运行；
2. 如何调整扫描参数（功率、失谐、轨迹数等）；
3. 如何导出结果，以及推荐的文件格式。

---

## 1. 环境准备

## 1.1 建议环境

- OS: Linux（Ubuntu/CentOS 均可）
- Julia: 建议 1.10+
- CPU: 多核（建议至少 8 线程，轨迹并行收益明显）

## 1.2 安装依赖

在仓库根目录运行：

```bash
julia --project -e 'using Pkg; Pkg.instantiate()'
```

首次会下载并预编译依赖（QuantumOptics、MAT、BenchmarkTools 等）。

---

## 2. 基本运行方式

## 2.1 快速试跑

```bash
julia --project -t auto -e 'using QuantumMC; using QuantumMC.MCWFOptimized; p=MCWFParams(); cfg=RunConfig(trajectories=10000, detuning=0.0, i_sat=0.6, seed=42); r=run_ensemble(p,cfg); @show r.count; @show sum(r.probability)'
```

说明：
- `-t auto` 自动使用可用线程数；
- `trajectories` 可以先用 1e4 小规模试运行，再提升到 1e6+。

## 2.2 固定线程数运行

```bash
julia --project -t 32 -e 'using QuantumMC; using QuantumMC.MCWFOptimized; println(run_ensemble(MCWFParams(), RunConfig(trajectories=200000)).count)'
```

建议在线程数 = 物理核心数附近做 benchmark，选择最快配置。

## 3. 参数扫描：怎么改

当前核心入口是：

- 物理参数：`MCWFParams(...)`
- 运行参数：`RunConfig(...)`

## 3.1 常用可扫描参数

### (A) 激光功率 / 饱和度

通过 `RunConfig(i_sat=...)` 调整。

```julia
cfg = RunConfig(i_sat=0.15, detuning=0.0, trajectories=200_000)
```

### (B) 失谐扫描

通过 `RunConfig(detuning=...)` 调整，典型可仿照 MATLAB 的 `spec_x = -1:0.1:1`。

```julia
detunings = -1.0:0.1:1.0
for Δ in detunings
    cfg = RunConfig(detuning=Δ, i_sat=0.6, trajectories=200_000, seed=20260406)
    result = run_ensemble(MCWFParams(), cfg)
    # 保存结果
end
```

### (C) 轨迹数

通过 `RunConfig(trajectories=...)` 控制统计精度和耗时。

- 开发调试：`1e4 ~ 5e4`
- 正式产出：`1e6+`（按服务器资源决定）

### (D) no-jump 更新步长

通过 `RunConfig(no_jump_step=...)` 调整。

- 小值：更精确，但更慢；
- 大值：更快，但可能引入数值误差。

建议在 `30/60/90/120` 上做收敛测试。

### (E) 动量窗口

通过 `MCWFParams(p=...)` 控制基维数 `num1 = 2p+1`。

- 增大 `p` 会显著提高计算量；
- 建议先检查边界动量态概率是否足够小，再决定是否扩大窗口。

## 4. 推荐的服务器批量扫描脚本写法

建议新建脚本 `scripts/run_scan.jl`（示例结构）：

```julia
using QuantumMC
using QuantumMC.MCWFOptimized
using DelimitedFiles

params = MCWFParams()
detunings = -1.0:0.1:1.0
powers = [0.15, 0.3, 0.45, 0.6, 0.75, 0.9]

rows = Float64[]
for pwr in powers, Δ in detunings
    cfg = RunConfig(i_sat=pwr, detuning=Δ, trajectories=200_000, seed=20260406)
    r = run_ensemble(params, cfg)
    # 依次写入: i_sat, detuning, count, probability_sum
    append!(rows, [pwr, Δ, r.count, sum(r.probability)])
end

writedlm("scan_summary.csv", reshape(rows, :, 4), ',')
```

运行方式：

```bash
julia --project -t auto scripts/run_scan.jl
```

## 5. 结果导出：文件格式建议

根据数据规模和后处理需求，推荐以下三种格式：

## 5.1 CSV（推荐用于汇总）

适合保存每个参数点的摘要量：
- `i_sat`, `detuning`, `count`, `runtime_sec`, `seed`

优点：通用、易用 Pandas/MATLAB/Excel 打开。

## 5.2 MAT（推荐与 MATLAB 对接）

可用 `MAT.jl` 输出 `.mat`，用于与 MATLAB 工具链无缝互通。

建议变量命名：
- `detunings`
- `powers`
- `counts`
- `probabilities`

## 5.3 JLD2（推荐大规模长期存档）

若轨迹记录或中间态数据很大，建议 JLD2（压缩率和读取速度更平衡）。

## 6. 与现有脚本的关系

- 正确性对标：`scripts/verify_against_matlab.jl`
  - 输入：`matlab_reference.mat`（变量 `probability_ref`）
  - 输出：最大误差与 PASS/FAIL

- 性能测试：`scripts/benchmark.jl`
  - 输入：轨迹数（可选 MATLAB 耗时）
  - 输出：Julia 运行时间、吞吐、speedup

建议流程：
1. 先跑 `verify` 确认正确性；
2. 再跑 `benchmark` 选最佳线程配置；
3. 最后执行参数扫描并导出结果。

---

## 7. 生产运行建议（服务器）

1. 使用 `screen`/`tmux` 或作业系统（SLURM）提交任务。
2. 记录完整元数据：
   - git commit hash
   - Julia 版本
   - 线程数
   - 参数范围
   - seed
3. 长任务建议分块保存（每完成一组参数即落盘），避免意外中断丢结果。
4. 对每次版本升级都做一次小规模回归（固定 seed + 固定参数点）。

---

## 8. 常见问题

### Q1：为什么多线程加速不明显？
- 可能线程数过高导致内存带宽瓶颈；
- 可能轨迹数太少，线程启动开销占比高。

### Q2：如何兼顾速度和精度？
- 从 `no_jump_step=90` 开始，逐步测试 `60/30`；
- 对比关键输出（峰位、峰高、总计数）变化是否可接受。

### Q3：如何做到与 MATLAB 更严格一致？
- 保持同 seed；
- 保证随机数消费顺序一致；
- 做逐步骤对比（单轨迹 debug 模式）。
